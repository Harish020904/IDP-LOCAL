What this project is

The deliverable is not a model. It is a documented, reproducible dataset pipeline whose output another researcher can regenerate from the same source data.

The goal

Transform the raw IoT-23 Zeek conn.log captures into a partitioned, documented, version-tagged Parquet dataset ready for NIDS model evaluation research. Every transformation is logged. Every row removed is attributable to a numbered operation. Every number in a report traces to a committed script.

What it is not
  • ✗ Not a model training pipeline
  • ✗ Not a benchmark evaluation
  • ✗ Not a feature selection study
  • ✗ Not a balancing or resampling exercise
  • ✗ Not a data download tool
The source

IoT-23 (Stratosphere Laboratory, v1.0.0) — 23 network captures from real IoT devices, 20 malicious and 3 benign, labelled at the flow level by security analysts. DOI: 10.5281/zenodo.4743746

Three-Plane Architecture

The laptop is a control plane only. The dataset never leaves Kaggle. This is the same separation a company makes between a developer workstation and a build farm.

Control Plane

Arch Linux laptop · harish · 12 GB RAM
  • agy CLI & agents
  • git + gh (code & docs)
  • kaggle CLI (push/pull only)
  • Obsidian vault (second brain)
  • Small reports, manifests, checksums
  • No dataset. No Parquet. No full CSVs.

Compute Plane

Kaggle Kernels · fixed image · recorded versions
  • Every row scan and column profile
  • Every join, transform, and test
  • Gate tests run on real data
  • Outputs written to /kaggle/working
  • Resumable per scenario (chunked)
  • Reproducible: same image, same packages

Storage Plane

Kaggle Datasets · versioned V0–V5
  • Dataset A: raw original — immutable
  • Dataset B: prepared outputs
  • V0 placeholder → V1 (M1) → V3 (M3) → V5 (M4)
  • Mounted at /kaggle/input/
  • SHA-256 verified every stage

Three-Agent System

Nobody merges their own work. The manager is the only merger, and only when both keys agree — manager review and tester verdict.

Manager · Controls main branch

manager

Assigns stages, reviews every PR against acceptance criteria, routes to tester, and is the only agent permitted to merge to main. Owns scope, review, and the merge decision.

May

read files run git/gh comment on PRs approve PRs merge to main assign stages

May not

write pipeline code merge without tester verdict fix defects approve without evidence pack
Data Engineer · Works on EDL-Pipeline

data-engineer

Implements one stage at a time. Writes notebooks and pipeline code, pushes to Kaggle, pulls back small outputs, writes gate tests and stage note, raises a PR for review.

May

read & edit files push kernels write tests raise PRs write stage notes

May not

merge approve own work download dataset locally run full scans on laptop
Tester · Independent verification

tester

Verifies independently against the requirements, not the code. Re-derives numbers with different tooling. Writes a five-line verdict. The one who does not share the engineer's mental model.

May

read files run verification kernels write review files search documentation issue verdicts

May not

edit pipeline code merge fix defects accept engineer's number without re-deriving
Tester Verdict Severity
S1 — FAIL · Veto
Rows lost silently, scenario crosses partition, label rewritten, raw data modified, balancing applied, parameter fitted on test data. Blocks merge and all further stage work.
S2 — FAIL · Rework
Required deliverable missing or wrong: no ADR for irreversible choice, gate test absent, report section empty, PR number contradicts artifact.
S3 — PASS WITH CONDITIONS
Docs or presentation defect: incomplete note, misleading chart, broken link. Fixable in a follow-up issue if manager agrees.
S4 — PASS · Note only
Cosmetic. Noted in the review but does not block the merge.

Ten Invariants

These hold in every stage, in every agent, at all times. Violating one is an S1 defect and blocks the merge.

Invariant 01
Raw data is read-only
The original archive is never modified, moved or re-extracted in place. Its SHA-256 is verified in every stage that touches data.
Invariant 02
Labels never silently changed
Corrections go in a new column (label_corrected) with a logged reason. Original label and detailed-label are never rewritten in place.
Invariant 03
No balancing, ever
No SMOTE, no oversampling, no undersampling, no synthetic flows, no minority deletion — anywhere. Stage 12 documents the imbalance; it does not fix it.
Invariant 04
No scenario crosses a partition
Whole scenarios go to exactly one partition. Never split a capture to force a rare label into every set. If a label exists in one capture, that is a documented limitation.
Invariant 05
Nothing fitted outside training data
Imputation values, scaling parameters, encoding dictionaries, category frequencies — computed on train only. Applied unchanged to validation and test. Fit source recorded with every parameter.
Invariant 06
Every removed row is attributable
Every deletion is a numbered operation in the cleaning log with field, condition, reason, and row count. Reconciliation identity: raw = cleaned + removed, exactly.
Invariant 07
Every number is reproducible
Every row count, percentage, and checksum in a report traces to a committed script or notebook that any reader can re-run.
Invariant 08
Every change is reviewed
Branch, PR, review, merge. No direct pushes to main. No self-approval. The manager is the only merger and only when both keys agree.
Invariant 09
No evidence pack, no review
A PR without all five evidence items is not reviewable, however good the code is. The manager will not open the diff.
Invariant 10
ADR before irreversible decisions
A decision that cannot be undone cheaply gets an Architecture Decision Record before it is implemented, not after.

Evidence Pack — Five Items, Every PR
Item 1
Test Output
Full-suite Kaggle kernel log with the exact command used. Not just CI's fast suite on the sample capture.
Item 2
The Numbers
Raw rows, removed, cleaned, reconciliation status, rare labels retained, output checksum across two runs.
Item 3
The Artifact
The committed report or manifest, referenced by path. Never pasted into the PR body.
Item 4
Stage Note
docs/02-stages/stage-NN-*.md written for someone who was not there. Numbers, not adjectives.
Item 5
ADR
Required if the stage made a choice that cannot be cheaply undone. Filed in docs/01-decisions/.
